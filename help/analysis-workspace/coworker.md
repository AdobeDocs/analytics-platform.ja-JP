# 従業員が製品内で体験できるようにしたい

>[!AVAILABILITY]
>
>このセクションで説明している機能は、リリースの限定テスト段階にあり、お使いの環境ではまだ利用できない可能性があります。 さらに、チームメンバーが生成AIを利用すると、不正確な結果や予期しない結果が生じる可能性があります。 共同作業者の反応と、それがプロジェクトに加えた変更を確認してから、それらを実行したり、プロジェクトを共有したりします。

Adobe Analysis Workspaceの右側のチャットパネルには、Adobe Workfrontの製品内エクスペリエンスが表示されます。 Coworkerでは、オープンなプロジェクトをコンテキストとして使用するので、分析について尋ねたり、プロジェクトに何が含まれているかを説明することなく、プロジェクトを構築してもらったりできます。

## Workspaceでの共同作業について

### 前提条件

* **Coworkerは組織で有効になっています**:Coworkerの製品内エクスペリエンスはデフォルトで無効になっています。 Customer Journey Analyticsの管理者は、ユーザーがアクセスする前に、その管理者を有効にする必要があります。

  WorkspaceでCoworkerにアクセスできない場合は、管理者にお問い合わせください。 詳しくは、[IMS組織の環境設定](/help/analysis-workspace/user-preferences.md#ims-organization-preferences)を参照してください。<!-- need to update this section with the new toggle -->

* **データビューへのアクセス**：共同作業者は既存のAnalysis Workspaceとデータビューの権限を使用します。 アクセス権のないデータやコンポーネントにはアクセスできません。

### WorkspaceのCoworkerとCoworker アプリケーションを選択します

Coworkerの製品内エクスペリエンスには、[CX Enterprise Coworker アプリケーション &#x200B;](https://experienceleague.adobe.com/en/docs/coworker/content/chat/use-cases/data-insights/analytics-chat)と同じ機能が多数あり、使用できるスキルも含まれます。 ただし、いつ使用するかを決定する重要な違いがあります。

| | 従業員向けの製品体験 | 共同作業者アプリケーション |
| --- | --- | --- |
| **使用するタイミング** | プロジェクトを作成し、他のユーザーと共有したり、時間の経過とともに更新したりします。 | 簡単な答えが必要です。 必要に応じて、後で分析をWorkspace プロジェクトに変換することもできます。 |
| **コンテキスト** | プロジェクト重視<p>開いているWorkspace プロジェクトをベースとして使用します。 既にプロジェクト内にあるパネル、テーブル、コンポーネントを参照して構築できます。</p> | データビュー重視<p>アクセスできるデータビュー、またはCoworker メモリの環境設定として設定したデータビューを使用します。 プロンプトに分析したい内容を記述します。</p> |
| **典型的なユーザー** | Workspaceで分析を構築および検証するアナリスト。 | Workspaceにアクセスしたり、情報を学んだりすることなく、疑問の答えを得たいビジネスユーザー。 |
| **出力** | Coworkerは、パネル、表、コンポーネントをWorkspace プロジェクトに直接追加します。 <p>適切な場合は、チャットでも回答します。</p> | 会話には回答と分析が表示され、Analysis Workspaceで開くこともできます。 |

### Coworkerで可能なこと

#### オープンプロジェクトに関する質問

次のような質問をすることができます。

* プロジェクトの概要：
* インサイトを見つけ出し、データの異常値をフラグ付けします。
* パネルで根本原因分析を実行します。
* 折れ線グラフを追加する方法や、値に基づいて表のセルに色を付ける方法など、Analysis Workspaceで行う方法について説明します。
* 指標やディメンションなどのコンポーネントについて説明します。

詳しくは、[&#x200B; プロジェクトに関する質問](#ask-questions-about-a-project)を参照してください。

#### 開いているプロジェクトのビルドと編集

Coworkerに次のようなことを依頼できます。

* 指定したディメンション、指標、日付範囲を含むフリーフォームパネルを作成します。
* プロジェクトにパネルを追加します。 Coworkerは、既存のパネルを上書きせずに新しいパネルを追加します。
* 表を分割するか、比較列を追加します。
* 表を折れ線グラフに変更するなど、パネルの日付範囲またはビジュアライゼーションタイプを変更します。
* パネルの名前を変更します。
* 既存のセグメントを名前で適用したり、平易な言語で説明を入力してセグメントを作成したり、セグメントをコピーしてロジックを変更したりできます。
* 日付範囲とシンプルな計算指標を作成。
* プロジェクトにインサイトを含む説明またはテキストビジュアライゼーションを追加します。
* 複数のパネルを使用してプロジェクトを作成するか、プロジェクトをコピーして、別のオーディエンスや地域に合わせます。
* プロジェクトを保存します。

詳しくは、[&#x200B; プロジェクトの更新](#update-a-project)を参照してください。

### 同僚がプロジェクトを更新したり、チャットで回答したりすると

チームメンバーは、チャットパネルで回答するか、質問に応じてプロジェクトを変更するかを決定します。 詳細については、[&#x200B; プロジェクトの更新](#update-a-project)および[&#x200B; プロジェクトに関する質問](#ask-questions-about-a-project)を参照してください。

また、従業員に対して何をすべきかを明確にすることもできます。 例えば、チャット _または_&#x200B;で&#x200B;_のようなフレーズを使用して、チャットパネルで回答を得るために_&#x200B;さんに伝えるか、このテーブル _で_ プロジェクトに追加&#x200B;_または_&#x200B;のようなフレーズを使用してプロジェクトを更新できます。

## プロジェクトで共同作業を使用する

共同作業者は、開いているプロジェクト内のすべてのパネルとテーブルを確認できます。 同僚に、プロジェクトに関する質問に答えたり、プロジェクトの更新を支援したりするように依頼できます。

>[!TIP]
>
>Coworkerを中断したり、プロジェクトをいつでも更新したりできます。
>
>* **タスクを開始または停止する**：同僚が作業している間に、**Shift+Enter**&#x200B;を押してさらに指示するか、**Esc**&#x200B;を押して停止します。
>
>* **Workspaceでプロジェクトを更新する**：共同作業者が作業している間にプロジェクトを編集すると、共同作業者は変更内容を認識します。

### プロジェクトの更新

プロジェクト内で何かを構築または編集するようにCoworkerに依頼すると、それに応じてプロジェクトが更新されます。 これには、_add_、_create_、_edit_、_break down_、_change_、_compare_&#x200B;などの単語で始まるリクエストが含まれます。 例えば、パネルや表の追加、データの分割、セグメントの作成などを同僚に依頼できます。

1. Customer Journey Analyticsで、既存のWorkspace プロジェクトを開くか、新しいプロジェクトを作成します。

1. ヘッダーの右上隅にある&#x200B;**同僚** アイコン ![同僚](/help/assets/icons/coworker.svg)を選択して、同僚のチャットパネルを開きます。

1. チャットパネルで、共同作業者に何を求めるかを記述します。

   次の表に、プロンプトの例を示します。

   | プロンプト | Coworkerの機能 |
   | --- | --- |
   | _先月のページ別のセッションを表示_ | 指定したディメンション、指標、日付範囲を含む新しいフリーフォームパネルを追加します。 既存のパネルは上書きされません。 |
   | _このテーブルをデバイス別に分割_ | 参照したテーブルに分類を追加します。 |
   | _このテーブルの先月との比較を追加_ | 参照したテーブルに比較列を追加します。 |
   | _このパネルの日付範囲を先月に変更_ | パネルの日付範囲を更新します。 |
   | _このテーブルを折れ線グラフに変更_ | パネルのビジュアライゼーションタイプを変更します。 |
   | _このパネルの名前をモバイルパフォーマンスに変更_ | パネルの名前を変更します。 |
   | _このパネルにモバイルユーザーセグメントを適用_ | パネルに既存のセグメントを適用します。 同僚はセグメント定義を知らないので、セグメントに期待が含まれていることを確認してください。 |
   | _カナダからの訪問者向けのセグメントを作成_ | セグメントを作成し、プロジェクトに追加します。 ページを更新すると、セグメントがコンポーネントリストに表示されます。 |
   | _カナダの訪問者セグメントをコピーして、メキシコの訪問者に変更_ | 更新されたロジックを使用してセグメントのコピーを作成し、それをプロジェクトに追加します。 |
   | _過去6週間の日付範囲を作成_ | 日付範囲を作成します。 日付範囲は、更新なしでコンポーネントリストに表示されます。 |
   | _セッションあたりの売上高の計算指標を作成_ | 計算指標を作成します。 チームメンバーは、シンプルな計算指標を作成できます。 |
   | _訪問数の減少を説明する説明をこのパネルに追加します_ | パネルに説明を追加します。 |
   | _主要インサイトを含むテキストビジュアライゼーションを追加_ | プロジェクトにインサイトを含むテキストビジュアライゼーションを追加します。 |
   | _トラフィック、コンバージョン、収益に関するパネルを含むプロジェクトを作成_ | 説明する各領域のパネルを含むプロジェクトを作成します。 |
   | _このプロジェクトをコピーして、EMEA地域に合わせます_ | プロジェクトのコピーを作成し、指定した地域に合わせて調整します。 |
   | _プロジェクトを保存_ | プロジェクトの保存。 |
   | _追加した分類を元に戻す_ | 指定した変更を元に戻します。 |
   | _古いパネルを削除_ | 削除する予定のパネルを一覧表示し、確認を待ってから削除します。 |

1. Coworkerがプロジェクトに加えた変更を確認します。 詳しくは、[共同作業者の結果の検証](#verify-coworker-results)を参照してください。

### プロジェクトに関する質問

プロジェクトについて質問すると、共同作業者はチャットパネルで回答します。 これには、_explain_、_summarize_、_discuss_、_詳細を教えてください_&#x200B;などのリクエストが含まれます。 根本原因分析の結果や同様のスキルも、同僚にプロジェクトに追加するように依頼するまで、チャットパネルに表示されます。

1. Customer Journey Analyticsで、既存のWorkspace プロジェクトを開くか、新しいプロジェクトを作成します。

1. ヘッダーの右上隅にある&#x200B;**同僚** アイコン ![同僚](/help/assets/icons/coworker.svg)を選択して、同僚のチャットパネルを開きます。

1. チャットパネルで、共同作業者に何を求めるかを記述します。

   次の表に、プロンプトの例を示します。

   | プロンプト | Coworkerの機能 |
   | --- | --- |
   | _このプロジェクトを要約_ | チャットパネルに概要が表示され、テキストビジュアライゼーションとしてプロジェクトに追加するオファーが表示されます。 |
   | _このプロジェクトでインサイトを検索_ | チャットパネルにインサイトを表示し、調査結果をプロジェクトに追加します。 |
   | _このパネルの異常にフラグを付ける_ | チャットパネルの異常値について説明します。 同僚にビジュアライゼーションで異常値を表示するように依頼すると、異常値が表示されない場合があります。 [現在の制限](#current-limitations)を参照してください。 |
   | _モバイル訪問の減少に関する根本原因分析を行う_ | チャットパネルに分析を表示し、調査結果をプロジェクトに追加します。 |
   | _値に基づいてセルに色を付けるにはどうすればよいですか？_ | チャットパネルの手順を説明します。 |
   | _バウンス率メトリックの説明_ | チャットパネルのコンポーネントについて説明します。 説明が[&#x200B; データ要素](/help/components/data-dictionary/data-dictionary-overview.md)から来ていません。 データディクショナリ定義のサポートは、今後のリリースで予定されています。 |

1. Workfrontの回答を確認する。 詳しくは、[共同作業者の結果の検証](#verify-coworker-results)を参照してください。

## 共同作業者の結果の検証

Coworkerは、結果の正確性をチェックするのに役立ちます。 見直す際には、次の点に留意してください。

* **同僚が作業を表示します**：同僚が質問に答えるために使用するセグメント、指標、フィルターがプロジェクトに追加され、ユーザーが確認できるようになります。

* **質問の明確化**：要求が曖昧な場合、または複数のコンポーネントと一致する場合、Coworkerは明確な質問を行うか、選択できるオプションを提案します。 例えば、複数の指標が使用した名前と一致する場合、Coworkerは一致する指標を提案します。

* **データ品質に関するメモ**：同僚は、データ品質に関するメモを回答に含めます。 例えば、始まったばかりの月と始まったばかりの月を比較する場合、Coworkerは、比較が部分的なデータに基づいていることを示します。

## 現在の制限事項

Coworkerの製品内エクスペリエンスには、次の制限があります。

* **セグメント定義**：名前でセグメントを参照すると、同僚はセグメントの定義を把握できません。 たとえば、チームメンバーは、セグメント名をもとにセグメントの内容を推測します。 結果に依存する前に、セグメント定義を確認します。

* **データ辞書**：同僚が[&#x200B; データ辞書](/help/components/data-dictionary/data-dictionary-overview.md)に接続されていません。 データ要素の定義を使用して指標とディメンションを説明することはできません。

* **承認済みコンポーネント**：同僚は、類似のコンポーネントよりも承認済みコンポーネントを優先しません。

* **パネルのコピー**：共同作業者はパネルをコピーまたは複製できません。

* **コンポーネントリストの新しいセグメント**:Coworkerが作成したセグメントは、ページを更新するまで、左側のパネルのコンポーネントリストに表示されません。 同僚が作成した日付範囲は、更新なしで表示されます。

* **異常値検出**：同僚にビジュアライゼーションで異常値を表示するように依頼すると、異常値が表示されない場合があります。

* **会話の履歴**：会話は、プロジェクトではなく、各ユーザーに対して保存されます。 プロジェクトを開く他のユーザーは、同僚との会話を見ることができません。 他のユーザーとコンテキストを共有するには、プロジェクト内のパネルの説明に追加します。

* **複数のブラウザータブ**：同じ会話を複数のブラウザータブで開くと、同僚が作業している内容を把握できなくなる可能性があります。

* **英語以外の言語**：英語以外の言語を使用するデータビューでは、Coworkerは回答に英語とデータビュー言語を組み合わせて使用できます。
